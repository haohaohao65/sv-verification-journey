# FIFO 验证计划草案

基准规格见 `dut_spec.md`。本文件保留阶段一拟定的完整目标；2026-10-16 已有 7 项定向＋3 个随机 seed 的功能回归与当前 covergroup 报告，证据见 [接续记录](../PROGRESS.md)。下列条目不因对应测试名称存在就自动视为全部验收，参数、覆盖模型和 DUT 错误注入仍需逐项核对。

## P0：先建立闭环

| ID | 场景与激励 | 自动检查目标 |
|---|---|---|
| P0-01 | 启动复位，保持跨越上升沿，撤销后 idle | empty=1、full=0、dout=0；复位期间读写无效 |
| P0-02 | 写入单笔非零 A，idle，再读取 | 写后 empty=0；写/idle 期间 dout 保持；读后 dout=A、empty=1 |
| P0-03 | 写入 A/B/C/D，再逐笔读取 | 顺序一致；无丢失/重复；每拍标志符合参考队列 |
| P0-04 | 连续有效读，每拍不同数据 | NBA 后输出对齐到同一拍请求；不漏连续读取 |
| P0-05 | 从非零 dout 开始进行 idle、只写及被拒绝读 | 输出保持；避免用全零数据掩盖意外清零 |

推进门槛：能够启动最小环境、解释驱动与采样；随后接入独立模型，无需看波形即可判断 P0。不要为赶进度提前实现全部 P1/P2。

## P1：边界、拒绝操作、复位和回绕

| ID | 场景与关键旧状态 | 自动检查目标 |
|---|---|---|
| P1-01 | q=D-1，再单写；q=1，再单读 | full/empty 在本拍更新后及时变化，无提前或滞后 |
| P1-02 | 写满后多次写入独特哨兵数据，再排空 | 拒绝写不覆盖已有数据；未接收数据不能后来被读出 |
| P1-03 | 排空且 dout 非零后，多次只读 | 队列不 pop，标志/输出保持；再次写读可恢复 |
| P1-04 | q=0，同时读写 A；下一拍只读 | 第一拍只接受写、dout 保持；第二拍读 A |
| P1-05 | 0<q<D，同时读写 | 读旧队首，写新尾部，数量不变；排空验证尾部数据 |
| P1-06 | q=D，同时读写哨兵 X，再继续读 | 本拍只接受读，full 清零；X 未进入 FIFO |
| P1-07 | 同时使能连续保持多拍，分别从空/中间/满开始 | 每拍都产生独立观测；接受条件随旧状态变化 |
| P1-08 | 多轮分批写读及交错操作 | 读/写各自跨越至少两次 Depth 次成功操作；回绕后顺序正确 |
| P1-09 | 非空/满/同时读写过程中复位，之后重填与排空 | 旧数据取消，dout 清零；新数据顺序与边界正确 |
| P1-10 | 时钟间异步断言 reset；短脉冲不跨上升沿 | 在无新时钟边沿情况下输出已复位；模型观察到事件 |
| P1-11 | 时钟保持不翻转时施加复位，再恢复时钟 | 证明异步断言；撤销时无操作，恢复后正确读写 |
| P1-12 | reset 高时 w/r 都为 1；安全撤销 | 复位分支优先，不存入高电平期间请求 |

回绕主要通过足够多的成功操作和读出数据验证；仅反复交替单写/单读不足以证明满态、积压和所有地址关系。

## P2：随机与参数

- 权重混合 idle、只写、只读、同时读写，包含连续 burst；记录随机种子和配置。
- 约束数据包含 0、全 1、普通随机值；有意使用不同值验证顺序，不能全程只写一个常量。
- 参数候选：`(Depth,Width)=(8,16),(2,1),(4,8),(16,32)`；非 2 次幂 `(3,8),(5,16)` 先作为支持调查，证实后纳入正式回归。
- Depth=1 单独记录位宽/工具行为，不能与已经确认的参数范围混写。
- 长随机过程中跨越空/满，插入活动中复位；不要把大量随机 idle 周期误当成有效验证工作量。
- 每组运行记录请求数、预期接受数、观测/检查周期数、复位次数、错误数、完成原因。当前已保存默认参数下 seed 1/42/2026 的随机回归；这不等同参数矩阵或所有随机目标已覆盖。

## 功能覆盖率计划

基础自动检查稳定后才加入功能 covergroup。Code coverage 统计 RTL 行/分支等被执行程度，Functional coverage 统计验证计划中的场景，两者不能相互替代。

| 覆盖点 | 来源/定义 | 注意事项 |
|---|---|---|
| 请求组合 00/01/10/11 | Monitor 的边沿前使能 | 覆盖连续使能的每拍请求 |
| pre 状态 empty/middle/full | 独立模型 q_pre | 不能从 DUT 错误标志分类 |
| 请求 × pre 状态 | 以上交叉 | 对 Depth>=2 的 12 个组合逐项确认 |
| 接受组合及拒绝写/读 | 根据 q_pre 计算、并通过检查验证的行为 | DUT 无 ack；标明是独立预测，不宣称直接测得硬件内部接受信号 |
| q_pre/q_post 关键边界和状态转移 | 模型状态 | 0、1、D-1、D；小深度去重，不设不可达 bins |
| 写入数据类别 | 仅在预期接受写且对应检查无误时采样 | 0、全 1、其他；Width=1 时没有“其他”类别 |
| 复位类型 | 启动/活动中/非时钟/短脉冲事件 | 与复位前占用交叉，时钟采样不能替代异步事件 |
| 读/写回绕 | 独立接受操作计数按 Depth 回绕 | 不使用请求数；配合读出顺序检查，属于模型推断的回绕 |

FIFO 存储接受行为没有独立应答端口，黑盒证明依赖后续读出数据与标志；覆盖命中不独立证明实现正确。失败运行单独保存，不能因覆盖数字高而计入通过结论。

## 完成与失败标准

1. Sequence 发完请求只代表生成结束；Driver item_done 的约定也不能替代 Monitor/Scoreboard 完成。
2. 定义每条观测的 cycle_id 和复位事件顺序。最后请求所在边沿已被 Monitor 发布，并被 Scoreboard 处理后，Test 才能结束。
3. 用最后必要观测的编号作为完成目标；确认无检查正在进行、analysis FIFO 无必须处理的遗留项，之后 drop_objection。
4. Monitor 还会观察 idle 周期，所以不能直接要求“全部观测数等于 Sequence 请求数”。具体终止屏障在阶段三设计。
5. 只有声明“排空结束”的测试才要求参考数据队列为空；测试完成时保留数据并不自动表示事务漏检。
6. UVM_ERROR、UVM_FATAL、断言失败、未知输出、随机化失败、超时、漏观测或漏检查均判 FAIL。错误/超时后退出必须向回归脚本传播非零退出码。
7. 超时是一条失败路径，固定 run 时间不是成功条件。复位可以清参考数据，不可以清已有错误数。
